## 〇、链路总图（S1→S7，括号内为数据流编号）

```
[S1 外骨骼背包+踏板 192.168.61.15]
   │ 12关节 ~800Hz / clutch 布尔
   ▼
[S2 T1 MessageBridge（vendor 二进制）]──(A) /exoskeleton/joint_states──┐
   │                                   (B) /clutch/{left,right} ──┐   │
   ▼ (经 ROS→IPC 9900 喂数)                                        │   │
[S3 T4 Puppetry（vendor 二进制）]◄─────────────────────────────────┼───┘
   │ 仅按住离合时发布 (C) /target_robot/{side}_ee/target ~100Hz     │
   │ 锚定参考 = (E) /target_robot/{side}_ee/state（经 MessageBridge IPC 回喂）│
   ▼                                                              │
[S4 T5 ik_node（250Hz pink QP）]◄──────────────────────────────────┘
   │ 订阅 (C)(B)(D:/client_robot/joint_states)；发布 (F) /target_robot/joint_commands
   │ [publish_commanded_ee_state=true 且按住时] 发布 (E) 指令FK ←—— 机制②回路点
   ▼
[S6 T3 exton_bridge]──(F)→ StepPlanner 计划 → TCP movej → [S7 控制器 192.168.61.60:30485]
   ▲                                                        │
   └──(D) /client_robot/joint_states ← 30Hz get_joint_position ←┘
   [S5 fk_adapter + robot_state_publisher] 消费 (D) → TF + (E) 真机FK（按住时让位）
```

## 一、S1 外骨骼背包 + 踏板（硬件层）

- 职责：采集操作员双臂 12 关节 + 踏板（左右=离合锁存，中间=手套标定）。
- 位置：硬件 192.168.61.15；无代码在本仓库。
- 现场观察命令：`ros2 topic hz /exoskeleton/joint_states`、`ros2 topic echo /clutch/left`。
- 故障模式：关节跳变/漂移（硬件）、踏板误标定（UBT P-024 教训：踏板语义贴标）、
  值锁存。→ 首查 S2 转发是否正常，再判定硬件。

## 二、S2 T1 MessageBridge（vendor 二进制）

- 职责：背包私有协议 ↔ ROS 话题双向转换；同时把若干 ROS 话题经 IPC 转喂 Puppetry。
- 位置：`DM-EXton2ProductPackage_tianchuang/Install/install_ros2/bin/ROS_2/MessageBridge`
  （二进制，无源码）；配置 `MessageBridge.yaml`（monitoring_ip=192.168.61.15）。
- 已知行为：订 (E) `/target_robot/{side}_ee/state` 并经 IPC 喂 Puppetry（22:17
  `topic info --verbose` 实证订阅者=本组件）。
- 故障模式：启动顺序依赖（先于消费者）、DOMAIN_ID 错配收不到。
- 首查：`ros2 topic hz /exoskeleton/joint_states`（有=背包→ROS 通）、
  `ros2 node list`、日志 `~/桌面/dm-exo/logs/T1_*.log`。

## 三、S3 T4 Puppetry（vendor 二进制）

- 职责：外骨骼关节 → 末端目标位姿（内部 pinocchio IK，100Hz）+ 锚定逻辑
  （把 (E) state 当真机状态）；**仅按住离合期间发布 (C)**。
- 位置：`Install/install_ros2/bin/Puppetry/Puppetry`（二进制）；配置
  `Install/install_ros2/bin/Puppetry/config/Puppetry.yaml`
  （use_ipc=true、interval_ms=10、enable_ik_solver=true、urdf_models/robot.urdf）。
- 关键未知（vendor）：对 (E) 是按下瞬间采样还是连续参考 → **T13 注入实验判决**；
  机制②（目标自漂移回路）的回路所在。
- 故障模式：目标流滑移（T11）、起流安定期自转 ~23°/s（ik_node 安定等待的设计依据）、
  断流停发（松开即停是设计行为）。
- 首查：`ros2 topic hz /target_robot/left_ee/target`（按住时 ~100Hz；松开=0 正常）、
  录包分析目标滑移（WORKLOG 23:01 判据）。

## 五、S5 T2 fk_adapter + robot_state_publisher

- 本地：`ros2_ws/src/robot_fk_adapter/robot_fk_adapter/joint_to_pose_adapter.py`（79 行）
- 职责：订 (D) → TF 查询 → 发 (E) **真机实测 FK**（`joint_callback` 44-50 行）；
  **`yield_when_clutch=True`（20-22 行）：按住离合时让位停发**（避与 ik_node 抢发）。
- robot_state_publisher：订 (D) 发 TF 树（URDF=hr_up_7dof_fixed）。
- **幽灵 TF 前科**（HANDOFF §三）：孤儿 robot_state_publisher 与现役同名帧并存 →
  FK adapter 随机取错树 → 轴置换+1.24m。**TF static 锁存**：清发布者后必须重启
  fk_adapter。启动脚本已加清理。
- 首查：`ros2 topic info /target_robot/left_ee/state --verbose`（发布者应有 1 个：
  松开=fk_adapter / 按住=ik_retargeting；**出现 2 个=双发布，机制②风险**）、
  pinocchio 离线 FK 对比（HANDOFF §三 方法，验自洽非验真机）、
  `ros2 run tf2_tools view_frames`。
