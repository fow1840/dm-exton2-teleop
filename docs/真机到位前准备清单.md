## 3. 向厂家 / 现场提前索取的协议证据

当前 V0.3 梳理没有完整定义下列字段。现场不要猜字段，也不要为了让脚本通过而放宽执行门禁。

| 接口 | 必须确认的内容 | 需要保存的证据 |
|---|---|---|
| get_device_state | 完整响应字段、state 在静止 / 运动中 / 故障时的合法值与状态迁移、错误码字段拼写、hardwareErrors / softwareErrors / motorErrorDetails 类型和清空语义 | 一份正常状态原始响应；若有历史故障，另给脱敏示例 |
| get_config | lowerLimits / upperLimits 长度、左右臂排列顺序、单位、限位是否为动态真值 | 完整脱敏响应和厂家字段说明 |
| get_joint_position | 17 维顺序、单位、实际反馈来源、刷新方式、是否有设备时间戳或序号 | 连续静止读数及运动时的更新机制说明 |
| get_tcp_pose | 14 维左右顺序、每段 xyz + 四元数顺序、位置单位、base / tool / TCP 定义 | 完整脱敏响应和坐标系定义 |
| movej | joint 数组顺序、-100 保持值、速度单位、应答表示“接收”还是“动作完成” | 成功 / 拒绝的应答样本及语义 |
| stop_motion | 适用状态、是否会中断当前动作、应答含义、故障状态下是否允许调用 | 厂家说明；现场由操作员验证停止流程 |
| TCP 连接 | 单连接约束、客户端所有权、连接冲突表现、超时后命令是否可能迟到 | 当前型号和固件版本说明 |

尤其注意：

1. T33 执行门禁要求 state、motorErrorDetails 等字段完整；V0.3 文档当前未定义其中部分字段。现场只读预检如果发现缺失，先找厂家确认，不要默认无故障。
   当前探针每次采样轮询都要求 state 为 idle / ready。厂家还必须说明 movej 回执是动作完成还是仅接收，以及运动期间 state 是否会变为 moving / busy；若状态机会返回其他值，T34 必须先按正式契约修改并补测，不能直接放宽白名单。
2. V0.3 未定义设备侧采样时间戳 / 序号。主机请求和接收时间不能证明设备反馈新鲜。现场必须确认反馈更新机制；无法证明时保持 UNCERTAIN / BLOCKED。
3. 控制器的 stop_motion 不是物理急停，也不能替代现场独立停止装置和操作员接管。
4. get_config 的 14 维限位顺序和 get_joint_position 的 17 维顺序必须分别核实，不能仅凭数组长度推断。

## 4. 真机到位后的只读阶段

### 4.1 T31：ROS 运行态采集

在现场 ROS 主机或同一 ROS 2 局域网主机执行。先从实际运行进程核实 ROS_DOMAIN_ID，再导出该值；不要直接照搬历史记录中的值。

~~~bash
T31_OBSERVATION=clutch_released \
bash tools/dm-exo/t31_readonly_audit.sh \
  /path/to/new-private-capture
~~~

- 脚本只读 ROS graph、参数、topic info、单帧样本和频率，不发运动命令。
- 采集目录由脚本以私有权限创建；原始样本可能包含现场运行信息，不要直接公开上传。
- 检查 status.tsv：退出码 124 表示有界采集超时，不等于测得频率；没有 average rate 必须标为未观测。
- 若要观察离合按下期间才发布的 target，只能在已有操作员批准的遥操窗口旁路观察；采集脚本不负责按离合。
- 若同一个 state topic 存在多个 publisher 且不能确定当前消息来源，T31 不得判 PASS。

### 4.2 T33：控制器只读预检

T33 增加了只读控制器检查模式。它依次请求 get_device_state、get_config、get_joint_position、get_tcp_pose，不发送 movej / stop_motion，不执行使能或故障复位。

~~~bash
python3 tools/dm-exo/urdf_fk_calib/urdf_axis_probe.py \
  /path/to/robot.urdf \
  --inspect-controller \
  --host YOUR_CONTROLLER_IP \
  --port 30485 \
  --rpc-timeout-s 1.0 \
  --output /path/to/private-capture/controller-preflight.json
~~~

- 当前型号 TCP 30485 是单连接。执行前必须由现场人员确认 T3 Bridge、示教 GUI 和其他客户端已释放连接；不能与遥操作同时运行。
- 输出文件必须是新文件，保留四类原始响应、主机请求 / 接收时间和 URDF SHA256。
- 此步骤只收集原始响应，不替现场人员判断字段语义；把字段、单位、顺序和反馈来源逐项核实后再决定是否放行 T34。
- 若状态异常、响应字段不完整、限位顺序不清或反馈新鲜度无法确认，停止在只读阶段。

## 5. T34：左臂真实物理方向验证（当前首个真机任务）

T34 是当前 P0-2。第一轮只验证一个由现场操作员根据当前限位余量、负载、构型和风险选定的左臂关节；五点试采与两次回位全部通过后，再按批准范围扩展至七轴。T30 历史翻转表任务已并入 T34，旧版无计划审批的直接命令和固定 +0.12rad 幅度不得使用。

**方向判定必须区分三种证据**：
- 历史 9 包 / 4435 样本：只证明 IK 指令与关节反馈的数值关系未见负相关，不观测真实 TCP 物理转向。
- T32 CSV/URDF：提供 J2L/J3L/J4L/J6L 的轴向候选差异，不证明真机轴向。
- T34 真机：使用实际关节角变化和实测 TCP 旋转，结合已核实的 base/TCP/frame，与当前 URDF 同姿态 Jacobian 预测比较。旋转点积为主判据；frame、反馈来源或信号不确定时只能记 UNCERTAIN。

### 5.1 运动前必须全部满足

- [ ] T31 运行态参数、话题发布端、frame_id 和左右坐标约定有证据。
- [ ] T32 审计报告已阅读；当前 URDF / CSV 的差异仅作为候选解释，不直接作为真机符号表。
- [ ] T33 离线测试通过，包含当前分支新增的故障响应和只读预检测试。
- [ ] 控制器状态字段、错误码、关节顺序、限位顺序、单位、TCP 顺序和反馈来源已核实。
- [ ] stop_motion 行为和现场独立停止流程已由厂家 / 操作员确认。
- [ ] T3 Bridge、示教 GUI、其他客户端已释放 TCP 30485；探针是唯一控制客户端。
- [ ] 现场人员在场，工作空间清空，防护、急停和停止手段有效。
- [ ] 操作员选定测试关节、基准姿态、正反向幅度、速度、回位容差、停稳标准，并明确批准本次计划。
- [ ] 基准关节角从真机实际反馈读取；不能用 URDF 零位或历史日志冒充当前零位。
- [ ] 测试关节在整个路径内有足够限位余量，扫掠空间无碰撞风险。

### 5.2 点位顺序

| 点位 | 动作 | 通过证据 |
|---|---|---|
| P0 | 当前基准姿态 | 真实关节角、左右 TCP、控制器状态 |
| P1 | 目标轴正向微扰 | 目标轴实际变化、其他轴保持、TCP 旋转 |
| P2 | 返回基准 | 实际回位误差 |
| P3 | 目标轴反向微扰 | 与正向可区分的反向运动、其他轴保持 |
| P4 | 再次返回基准 | 第二次实际回位误差 |

探针一次只测试一个关节。delta、speed、容差和停稳时间必须从现场基准、噪声、限位余量和操作员批准中确定；本文件不预填通用运动幅度。

### 5.3 结果分类

- ALIGNED：正、反两个方向的 TCP 旋转方向都与当前 URDF 预测一致。
- INVERTED：正、反两个方向的 TCP 旋转方向都与当前 URDF 预测相反。
- UNCERTAIN：信号不足、正反结果不一致、反馈来源不清或帧定义未确认。
- 单关节通过只说明该轴和采样链路通过；左臂七轴必须逐轴完成，不能由一个关节外推整臂。

出现控制器故障、反馈冻结 / 过期、控制权冲突、异常运动或回位失败，立即停止继续派发采样点，保存原始数据和中止原因，由现场操作员接管。禁止自动恢复、自动使能或自动回位。

## 6. 原始证据包结构

建议每次现场试验建立独立目录，原始数据只保存在现场批准的位置：

~~~text
T34_YYYYMMDD_runNN/
  runtime_t31/             # ROS 参数、topic、frame 原始只读采集
  controller_preflight/    # get_device_state / config / joint / TCP 原始响应
  plans/                   # 经操作员批准的计划 JSON 与审批摘要
  probe/                   # 原始 JSONL，包含目标、实际反馈、回执和中止原因
  analysis/                # Pinocchio 分析输出、方向分数、结论
  summary.md               # 脱敏结论、软件版本、URDF SHA256、证据索引
~~~

原始文件只追加、不覆盖。每次试验记录控制器型号 / 固件、URDF SHA256、工具与基座定义、软件 commit、操作者批准、开始 / 结束时间和现场变更。公开 GitHub 只提交脱敏摘要和受控证据引用。

## 7. 放行结论

真机抵达前的代码与离线准备完成，不代表 T34 已获准执行。只有第 2 节离线验收通过、第 3 节协议证据补齐、第 4 节只读检查通过，以及第 5.1 节现场清单全部勾选后，才允许操作员批准第一次单关节运动。

任何字段缺失、协议不一致、反馈新鲜度无法证明、控制器故障或停止行为未确认，都保持 BLOCKED；不得通过删校验、降低安全门槛或改成远程自动使能来“完成准备”。
