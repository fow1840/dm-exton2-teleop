# T32 左右臂 URDF / CSV 关节轴离线审计

审计基线为仓库提交 60370a5872d26a64a14da32623f96d6dc015852a。计算只读取仓库模型和已存样本。

## 结论

- **已证实｜四份同型号 URDF 的 14 个关节运动学定义相同。** 当前工作区版 W、产品包固定版 P、下载版 D、演示源码版 E 的关节名称、顺序、类型、parent/child、origin 和 axis 全相同。安装变换数值一致。用相同关节角计算，两臂末端位置和姿态均一致。下载版和产品包固定版没有提供不同的关节轴候选。
- **已证实｜原始 CSV 与 URDF 的差异集中在左臂。** CSV 右臂关节定义与四份 URDF 一致。左臂 J1L～J7L 的 origin RPY 全不同，J5L 和 J6L 的 XYZ 还有符号变化。局部 axis 均为 +Z，换到同一基座后，CSV 左臂 J2L、J3L、J4L、J6L 的轴方向与 W 近反向。两种模型定义的中性位姿也不同。
- **推测｜零位和局部坐标约定需要优先查。** 文件的关节拓扑相同，对应 origin 平移的长度相同。相邻轴的夹角和线距也近乎相同，现有文件证据不足以归因为连杆长度改变。
- **未验证｜真实关节零位、符号和 TCP 定义。** 历史样本缺少独立右臂扫姿和单关节扰动，不能从本报告指定真机翻转表、判定轴置换或把 CSV 直接当成真机模型。T34 应先核对现场基座、TCP、角度单位与读数来源，再用单轴正反微扰验证。

## 可复现离线校验（GPT-6 复核补充）

仓库新增标准库实现的显式链式 FK / CSV 审计脚本，独立复核 14 个关节的统一基座世界轴向、四份 CSV 字节一致性、四份 URDF 关节运动学字段，以及 L-1 历史姿态和真正 q=0 的 FK 差异：

~~~bash
python3 tools/dm-exo/urdf_fk_calib/audit_urdf_csv.py
python3 tools/tests/test_t32_urdf_csv_audit.py -v
~~~

关键复核值：
- 四份 CSV 的 Git blob 相同；脚本还会逐字节核对 SHA256。
- W / P / D / E 的 14 个机械臂关节 type、parent/child、origin xyz/rpy 和 local axis 一致；安装固定关节 parent 命名差异单独处理。
- CSV 左臂相对 W 的统一 base_link 世界轴 dot：J1L +1、J2L -1、J3L -1、J4L -1、J5L +1、J6L -1、J7L +1；右臂七轴均 +1。
- L-1 的 q17 按腰 + 左七轴 + 右七轴 + 头两轴解析，左臂取 q17[1:8]。该姿态 W/C FK 差为 1193.9109 mm / 167.9297°；q=0 则为 1196.8000 mm / 179.9992°。
- 样本 FK 只用于核对历史记录，不证明真实零位、关节符号、控制器 base 或 TCP 定义。不得把 CSV 候选符号直接写入 URDF / Bridge。
