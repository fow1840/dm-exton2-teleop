## 一、信号链路全景（✅ 代码实证）

```
外骨骼背包 192.168.61.15（12关节，~800Hz）
  │
  │ T1 MessageBridge（ROS2 DOMAIN 42）
  ▼
/exoskeleton/joint_states ─────────────► T4 Puppetry（vendor 二进制，100Hz 目标流）

                       │                  ▼
                       │          /target_robot/{left,right}_ee/target

  按住离合时让位停发                      且按住离合时）——发的是【指令 FK】不是实测 FK！
  ▲                                  │
  │                                  ▼
  │                        T3 exton_bridge（command_rate_hz 节拍）
  │                          _flush_commands：err = IK指令 − 真机反馈fb
  │                          目标 = fb + clip(err, ±0.20rad)，|err|≤0.001rad 不发
  │                          movej lock-step：等 status 应答才发下一条，300ms 超时
  │                          30Hz get_joint_position → /client_robot/joint_states ──┐
  ▼                                                                                 │

```

### 关键闭环结构（本次分析的核心结论）

整条链路里**叠加了三个串联的闭环**，全部以「真机/指令的位置差」为驱动：

1. **IK 内环（250Hz）**：`solve_ik` 让指令关节角去追目标末端位姿。
2. **bridge 外环（command_rate 节拍）**：`_flush_commands` 每拍用**真机反馈**重算
   `err = Q_ik − fb`、`目标 = fb + step`（`exton_bridge.py:581-593`）。只要 |err| > eps
   就发一条 movej。**这意味着 IK 冻结 ≠ bridge 停发**——bridge 自己会持续纠偏。
3. **Puppetry 锚定环（100Hz）**：Puppetry 把 `/target_robot/{side}_ee/state` 当「真机当前
   状态」，按住离合期间该话题由 ik_node 发**指令 FK**（fk_adapter 让位）→ 见机制②。

## 二、「离合后手臂自己移动」的机制拆解

### 机制① IK 指令层手静自运动 —— ✅ 已修复（T10，23:01 部署）

残余末端误差在近奇异构型（左 J7）下被放大成大幅关节调整（手静 0.5s J7 −7.5°）。
修复 = 按滤波后目标速度判定手静（5mm/s / 0.05rad/s），手静时跳过该臂 solve_ik。
实测：探针峰值 16.3mrad（修复前 5935mrad），包 `press01_left_230820.npz`。
**不再展开，详见 HANDOFF §四。**

### 机制② Puppetry 目标自漂移回路（T11）—— 🔍 本次分析把回路具体化

**数据流事实（✅ 代码实证）**：

- `joint_to_pose_adapter.py:47-48`：`yield_when_clutch=True` → 按住离合期间 FK adapter
  **停发** `/target_robot/{side}_ee/state`；
- `ik_node.py:540-541`：同一期间由 ik_node 接管该话题，发的是
  **`q_commanded` 的指令 FK**（不是真机实测）；
- `Puppetry.yaml`：Puppetry 经 MessageBridge IPC 消费该话题（22:17 `ros2 topic info
  --verbose` 显示订阅者=message_bridge，与此一致）。

**回路机制（🔍 推断，量级吻合）**：若 Puppetry 在按住期间以该话题为连续参考合成目标
（target ≈ state + 按下时的 bias 常数 C），则手静时：

```
指令FK移动 → state 跟着移动 → target = state + C 跟着移动 → IK 继续追 → ……
```

IK 的末端误差恒等于 C、永不收敛，漂移速率 = IK 闭环收敛速率。按住期间
target 滑移最高 10.2mm/0.5s ≈ 20mm/s（w=327.992）、全按住段 IK J1 净 −11.09°，
与该机制量级吻合。**注意：这同时解释了为什么「手静冻结」治不了它——20mm/s 高于
5mm/s 冻结阈值，IK 是在「合法跟随」一个自己喂出来的漂移目标。**

**判别实验（部分完成）**：`publish_commanded_ee_state` 已置 False（23:16，IK pid 79431）。
23:30 操作员口述复测：手臂**仍动，幅度主观变小**（无录包，归因未验证）。解读：
- 幅度变小 → 机制②可能确有贡献（⬜ 待新包量化）；
- 未消除 → 至少还存在另一条驱动路径——机制③（bridge hunt）嫌疑权重上升，
  或 Puppetry 对 state 的依赖不止这一条路（比如它自身对 state 的其它用法）。

**若实锤，永久修复候选（按语义正确度排序）**：

| 方案 | 做法 | 代价/风险 |
|---|---|---|
| a. 发实测 FK | ik_node 按住期间改发 `q_measured` 的 FK（而非 q_commanded） | 话题语义恢复「真机状态」本意；回路经 bridge→真机物理链，带宽低 ~2 个量级，残余漂移应远小于 20mm/s。⬜ 未验证 |
| b. param=False 永久化 | 按住期间无人发 state，Puppetry 用按下前最后一帧锚定 | 若 Puppetry 只在按下瞬间采样 state，无损失；若它持续消费，行为未知（vendor 二进制）⬜ |
| c. 发冻结锚 | 按住期间 state 恒发「按下锚定位姿」 | 与增量遥操语义一致，但 Puppetry 对恒定 state 的反应未知 ⬜ |

在真机复测前，可先做**离线注入实验**（不动机器人、不按踏板）：停 bridge，用
`ros2 topic pub` 注入 /clutch/left=true + 回放录包的外骨骼流 + 人工正弦 state，
观察 `/target_robot/left_ee/target` 是否跟着 state 走——直接刻画 Puppetry 对 state
的连续依赖（→ T13）。

### 机制③ bridge 第二闭环 hunt（T12）—— 🔍 本次分析新提出，有两条硬证据

**证据 1（✅）**：23:08 测试期间 bridge 拒绝计数 19→59——IK 指令冻结的窗口内 bridge
**仍在发 movej**（冻结臂的 `ik_rng=0.000` 窗口里真机仍在动，rob_rng≈2.2°）。

**证据 2（✅ 代码）**：`_flush_commands` 以真机反馈为底闭环纠偏，
`command_eps_rad=0.001rad=0.057°`（`exton_bridge.py:409`）——远小于 movej 程序的
实际到位/复现能力。真机只要停在离 Q_ik 0.057° 以外，bridge 就再发一条。

**机制（🔍）**：每条 movej 是完整 P2P 程序（v=15，小行程约 ~1s 节拍，与观测振荡
周期 ~1s 吻合）；纠偏→真机运动→反馈更新→再纠偏，若真机每次到位有过冲/欠达
（ack 语义、伺服整定、摩擦/静摩擦），就形成 **~1Hz 多关节同相位的 hunt 极限环**
（观测：J1 ±2.2~2.9° 交替，J3~J6 同相关小幅跟随——整个臂来回摆）。
`movej_tx=2092 ack=2092 timeout=25` 说明 ack 通常 <300ms 到达——**ack 更像
「程序受理」而非「运动完成」**，这会让 lock-step 失去按运动周期串行的作用。

**判别实验（T12 计划的落地化）**：
1. 对齐 T3 日志 movej 发送/拒绝时间戳与 /rob 振荡窗口（台账 T12 原计划）；
2. **单步 movej 台架**（需停 bridge，TCP 单连接）：joint_probe 发一条到 3° 外固定位姿的
   movej，观察 status 回复时刻 vs 反馈稳定时刻 vs 是否过冲。单步干净 → hunt 是
   bridge 连发驱动；单步过冲 → 控制器侧问题（伺服/整定）。

**修复方向（若确认 bridge 驱动）**：hold + 迟滞——
- 收敛判据：|err| < 0.01rad（0.57°）即认为到位，**停发**；
- 重启动阈值：|err| > 0.03~0.05rad（1.7~2.9°）或 IK 指令变化才恢复发；
- 即 UBT P-007 根治「限速器自激极限环」的同款思路（死区打破自激），只是死区
  加在 bridge 层而不是 IK 层。真机验收看：手静窗内 movej_tx 停止增长、J1 振荡消失。
