# URDF 真机验收方案 —— 适配前强制门禁（P0）

> 目的：**URDF 正确性是适配前优先检查对象**。任何 URDF（厂商原生、`-fixed` 修改版、
> T39 数值重建版）在接入遥操链（IK 求解 / bridge 限位 / RViz / 碰撞检查）之前，
> 必须先通过本方案的真机对账验收，确保「模型 = 真机」，而不是接进去之后靠调参数硬凑。
> 为什么是 P0：T20 实锤——不合格 URDF 进链路的代价 = 结构性残差 292~1895mm、
> 姿态残差 100~167°、肩膀方向与遥操相反、限位 fault；全部下游（T29 方向校准等）被它卡死。
> 适用：新机器人接入 / URDF 更换或重建 / 标定与换件后的回归。
> 配套：采数与重建见 [URDF数值重建采数方案.md](./URDF数值重建采数方案.md)；
> 方法论与前提见模板库 `URDF自重建方法论.md`；对账历史见 [UBT_URDF对账方法论.md](./UBT_URDF对账方法论.md)。

## 门限（先声明后验收，不得验收后挪门限）

| 维度 | 门限 | 依据 |
|---|---|---|
| 位置残差（20 组，逐样本 max） | **≤ 20mm** | ≈机械臂绝对定位精度下限（持久记忆/台账） |
| 姿态残差（20 组，逐样本 max） | **≤ 2°** | UBT M5②：只验位置会漏 90° 恒差 |
| 符号可救性枚举（s∈{±1}^n） | 救不回 = 结构性 | UBT P-016 判决法 |
| 回归简版（G4，5 组） | 同上双维度 | 防「标定复活旧病」 |

## 数据需求与采样分档（约窗口前先读）

**五道门里只有 G3 需要真机数据**——而 G3 恰是唯一能回答「到底匹不匹配」的门。
流程按「先便宜后昂贵」排序，为的是让真机数据花在刀刃上：

| 门 | 真机数据 | 成本 | 能拦住什么 |
|---|---|---|---|
| G0/G1/G2 | ❌ 纯桌面 | 分钟~小时级 | 限位过时、镜像隐患、关节序错、TF 接错——避免拿硬伤 URDF 浪费窗口 |
| **G3** | ✅ **必须** | ~20min/臂 | 「模型=真机」的最终判决；桌面检查再干净也证明不了匹配（G2 的 0.0mm 自洽误判即教训） |
| G4 回归 | ✅ 5 组简版 | 分钟级/次 | 标定/换件后旧病复发 |

**采样 ≠ 驱臂**：G3 首选「操作员摆位姿 + 脚本只读采集」（collect_samples 模式）——
电机零指令、零运动风险，~15-20 分钟采完 20 组，不需要 enable 之外的运动授权。

**数量分档（各干各的事）**：

| 档 | 数量 | 用途 |
|---|---|---|
| 粗判决 | 6 组 | 足够判「结构性不可救」（T20 即 6 组判死） |
| **标准验收** | **20 组** | G3 门限；覆盖高位/低位/近身/外缘/近奇异 |
| 重建用 | 60 组 | 仅 G3 判「不可救」走 T39 重建时需要 |

**一批数据多处复用，不是每次适配从零采**：20 组验收数据 → 判「不可救」时并入重建种子
（60 组的组成部分）→ 适配完成后当 G4 回归基线。

**成本最优实操序**：

```
拿到 URDF → G0/G1/G2 当天桌面做完（发现硬伤先修，别上窗口）
  → 真机窗口：操作员摆 20 位姿，只读采完 → compare_fk 一键判决
      PASS → G4 冻结，开始适配（IK/限位/RViz 接入）
      符号可救 → 翻转表修正 → 重跑 G3
      结构性不可救 → 厂商索取 或 T39 重建（60 组，含已有 20 组）
```

## 五道门（G0→G4 串行；任一门不过，禁止进入下一门，禁止接入遥操链）

### G0 资料层（纯桌面，先便宜后昂贵）

- [ ] URDF 来源、版本、**修改记录**可追溯（`-fixed` 版修过什么没人知道 = 红旗，T20 教训）
- [ ] 文件 md5 落台账
- [ ] **限位三方对比**：URDF 限位 = 厂商档案 = 实机直读（get_config 类）；不一致时**实机直读为权威**，
      差异逐轴列表（EX 实例：URDF ±170° 一刀切 vs 实机 J2=[-135°,+14.9°]，J3 差 130.5°）
- [ ] 关节数与协议维数对上（EX：协议 17 维 = 腰 + 左 7 + 右 7 + 头 2）

### G1 静态结构层（桌面，URDF 源文件检查）

- [ ] 关节名 / 顺序 / 父子链与协议关节序一致（EX：协议序 腰/L1-L7/R1-R7/摇头/点头）
- [ ] 轴向齐性检查：全 axis=[0,0,1] 是常见约定，出现非 z 轴要能解释
- [ ] **左右臂镜像性检查**：左右链 origin 逐字 diff——「非简单镜像」（如 Joint1 z=-π vs Joint1L z=0）
      是镜像建模隐患形态【EX：源 CSV 对比发现，待真机判决】
- [ ] 零位定义明确：URDF 零位 = 电机零位吗？差多少（INIT 偏移）？【S2：SDK 零位=前伸 ≠ URDF 零位=垂臂】
- [ ] 末端是否有漏掉的固定旋转/工具偏移【S2：漏 Rz(π/2) → 真机手腕旋到限位】

### G2 自洽层（不需要真机，上电前可做）

- [ ] 同一 URDF 下：robot_state_publisher 的 TF vs pinocchio/自写 FK = 恒等（0.0mm/0.0°）
- [ ] **注意语义**：本门只证「实现自洽」（TF 链没接错），**不证 URDF 匹配真机**——
      EX 曾把 0.0mm 自洽误当真机检查，T20 才补上真判决

### G3 真机对账层（核心门，需真机；只读优先）

采样模式（按安全序选）：
1. **操作员摆位 + 只读采集**（collect_samples.py 模式）：零运动风险，首选；
2. 小步驱动采数（sweep_calib.py / sweep_v2 护栏）：限位内缩、禁区剔除、步进 0.005rad/帧、
   每步 device_state 复查、反馈活性门、操作员在场——仅在摆位模式覆盖不足时用。

采样要求：
- [ ] ≥20 组独立构型（去重后；EX 教训：5 条同构型重复读数只算 1 组）
- [ ] 覆盖：高位/低位/近身/外缘/近奇异；腰固定；采数臂之外全静止
- [ ] 双维度记录：q 全关节 + TCP 位姿（注意四元数序、单位——用已知基线校准过才算数）
- [ ] 反馈活性验证：驱动后反馈必须变化（防缓存冻结数据，T26 签名）

判决（compare_fk.py 一键出）：

| 判决 | 判据 | 处置 |
|---|---|---|
| **PASS** | 位置 ≤20mm 且姿态 ≤2° | → G4 冻结 |
| **符号层可救** | s∈{±1}^n 枚举 + 偏移拟合救回 | 翻转表/映射修正（T30/T34 探针定表）→ 修正后**重跑 G3** |
| **结构性不可救** | 枚举救不回（EX：292~1895mm） | **禁止接入链路**；走厂商索取或 URDF自重建方法论（T39）；重建产物回到本门重新验收 |

### G4 冻结与回归层（验收通过 ≠ 一劳永逸）

- [ ] 通过的 URDF md5 + 验收报告入台账（WORKLOG + 本文件 §3 模板）
- [ ] 此后**每次**标定、重部署、换件、URDF 重新生成后：跑 G3 简版（5 组）回归
      ——标定是运行时状态，防旧修复被标定复活（用户级纪律）
- [ ] IK / bridge 限位 / RViz 引用的 URDF 副本与本门通过版 **md5 一致**（有副本必须同源）

## §2 执行注意

1. 采样优先只读模式；驱动模式按「首次自动动作逐段小步、人在旁目视、异常即停」执行。
2. 真机窗口稀缺：G0/G1/G2 全部离线先做，窗口只做 G3 采样 + 判决。
3. GUI 读数与协议反馈存在可疑偏差（EX：J5R/J7L 未定论）——对账一律以协议反馈为真值源，
   GUI 只作旁证。
4. 「厂商档案说高度一致」必须实测复核【S2 教训】；静态资料先核对再用。
5. 验收结论必须附原文证据（残差表/命令输出），转述不算。
