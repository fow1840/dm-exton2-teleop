## 一、故事线：从一条经验记录到 0.001mm 对账

### 第 1 幕：症状先以经验记录形式存在（P-008 之前）
最早的记录只是一句话（HANDOVER §九）：「**Puppetry URDF 的右肘符号是错的**，
限位以 SDK `s2_arm_constants.h` kLeft/RightJointLimits 为准」——当时**不知道**
这是深层次不匹配的症状，只是作为避坑经验在传。

### 第 2 幕：真值源先行（P-008，2026-10-12）
P-008（B 键复位安全分析）需要可信 FK 做碰撞裕度计算。做法：
- 从闭源 SDK 的**头文件** `s2_arm_constants.h` 直写 D-H FK（`p008/sdk_fk.py`，
  θ=q+INIT 标准链，可出肘点）；
- 真机采 **20 组数据**（q_exec 7 关节 + SDK 末端点，waist_pitch 系；18 左臂 + 2 右臂，
  `/tmp/sdk_probe_p008` 探针采样）；
- D-H FK 对 20 组验证：**残差 0.0008mm** → D-H FK 从此有资格当「裁判」。

### 第 3 幕：结构性判定——「符号错」只是症状（P-016/M0，同日）
pink 迁移需要 URDF，且必须先回答「URDF 键还是执行器键谁是正确约定」。
用户指令：**先真机确定这一步**。四条证据链：

| 证据 | 内容 | 作用 |
|---|---|---|
| 1（权威） | SSH 只读读出 `s2_arm_constants.h` 限位：**两臂逐项完全相同**（双肘弯曲均为负） | 执行器/SDK 约定统一 → 它是权威（它驱动机器） |
| 2（对照） | 两个库存 URDF（s2_v1_world 与 Puppetry robot.urdf，**md5 逐字节相同**）都是**镜像建模**（左右限位互为镜像），且 SDK 零位=双臂前伸（INIT={0,π/2,...}）≠ URDF 零位=垂臂 | 至少一臂符号相反 + 零位结构性不同 |
| 3（判决） | **枚举 s∈{±1}^7 符号 × scipy LM 拟合偏移**，对 20 组真机数据：库存 URDF max **321~388mm**（门限 20mm）、肘点 454mm → **符号+偏移映射救不回来** | 符号错误会被 ±1 枚举吸收；救不回 ⇒ 轴系/零位**结构性**差异 ⇒ **宣判不可救，不修补** |
| 4（兜底） | 活体 robot_state 无数据（开发者模式关，P-015 同源） | 真机判定以头文件 + 当天真机实测数据为准 |

### 第 4 幕：正解=同源重建，而非修补（M0 定案）
`gen_sdk_urdf.py` 从**与真值源同一份 D-H 常数**合成 URDF
（q_urdf = q_exec 恒等零映射），**同一 20 组数据**回归验证：
腕点 max **0.001mm**、肘点 **0.000mm**。
效果：pink 的输入输出全部落在执行器键空间，与 C++ 生产节点同键——
把「关节符号映射」这个安全级风险**归零**（而非缩小）。

DH→URDF 构造要点（踩坑防复发）：每步 `T_j = Rz(θ_j)·C_j`，θ_j = q_exec + INIT_j，
C_j = Tz(d)Rx(α)Tx(a)；**Rz(INIT)·C_j 烘进下一关节的 origin**，且 Rz 必须左乘
旋转平移后的 t（否则出现恒定 20mm=|a3| 错位）；link_k 原点对应 chain[k-1]
（命名滞后一位）。

### 第 5 幕：验证盲区在真机暴露（M5 ②，2026-10-13）
M0 只验了**位置**。真机切 pink 后「**手腕持续旋转到限位**」→
合成 URDF 末端 fixed 关节漏了 DH 第 7 步后的 `Rz(π/2)`（位置无关、恒差 90°）。
pinocchio 实测：修复前 `worst_rot=90.000000°` → 修复后 `0.000000°`
（位置始终 0.001mm）。**教训：位置回归必须配姿态回归，缺一即盲区。**

### 第 6 幕：帧差是另一类问题，单独标定（P-012 坑 + M5 ①）
- P-012 方法论坑：外骨骼目标流位置与 D-H FK **不可直接笛卡尔对比**
  （差值非常量，y 向 std 0.36m）→ 两套坐标并存时跨系分析只能用相对量/关节量，
  除非先做帧标定；
- M5 ①：目标流平铺 API「torso frame」vs pink 模型 D-H 实例帧，缺固定变换 X_map
  → D-H 锚点与平铺帧目标固有 **~1m 偏差**被 3s 软启动压缩执行 = **离合瞬间手臂猛动**；
- 标定方法：`fk_probe` 直调平铺 `CalcEndPose`，**零位单点即可 + 21 组复核**，
  残差 **0.0000mm/0.0000mrad**，烘成常量 `X_MAP_INV` 进代码 + 一键启动脚本门禁
  （缺常量拒绝启动）。

### 第 7 幕：数据纪律（差点制造假结论）
初版把 20 组数据中第 7/8 组的 q_exec 与 sdk_end **配对抄串（错位一行）**，
制造出「176mm 残差」假象。定案教训：**标定数据必须与原件逐字 diff；
异常残差先查数据配对，再查算法。**

## 二、方法论提炼（七条可迁移规则）

1. **先建真值源，再当裁判**：从控制器自己的定义（头文件 D-H / 厂商 FK）直写 FK，
   用真机实测数据验证到 mm 级残差，才有资格评判其它模型。
2. **权威分级**：驱动接口的约定是唯一权威（它就是驱动机器的接口）；URDF/文档只是
   描述，可以与权威矛盾——矛盾时修描述，不修权威。
3. **便宜的一锤定音检查先行**：限位表对比（双臂同/异、数值对不对）是行级代码的
   证据量，却常常直接判决（M0 证据 1 就来自 18 行头文件）。
4. **可救性要用枚举拟合判定**：s∈{±1}^n × 偏移 LM 拟合，残差远超门限 ⇒ 结构性差异，
   宣判不可救；**不要在「修补错误模型」上花时间，直接从真值源重建**。
5. **同源重建 + 同数据回归**：重建用的常数必须与真值源同一份；验证必须用同一批
   真机数据；**位置与姿态两个维度都要回归**（第 5 幕的 90° 就是漏了姿态）。
6. **两套坐标并存 = 必须标定 X_map**：零位单点初标 + 多组复核 + 烘成常量 +
   启动门禁；跨系分析在此之前只能用相对量/关节量。
7. **数据纪律**：标定数据与原件逐字 diff；异常残差先查数据配对再查算法。

## 三、对 DM-EXton2 的适用性（对照现状，引出 T20）

| UBT 检查项 | DM-EXton2 现状 | 状态 |
|---|---|---|
| URDF vs 真机运动学对账 | **从未做过**。已有的「FK adapter vs pinocchio 0.0mm」是同一 URDF 的自洽性检查（TF 来自 robot_state_publisher，同一个 URDF），**不是真机检查** | ⬜ 空白 |
| 限位表对比 | 已见疑点：J7 URDF 限位 ±2.967rad(±170°) vs 档案软限位 ±152.7°（T06 在查）；URDF 是厂商「-fixed」版，修过什么无记录 | ⬜ |
| 姿态维度回归 | 无任何姿态对账（M5 ② 的盲区在本项目同样存在） | ⬜ |
| 帧标定（X_map 等价物） | mirror_xyz=[1,1,1] 的注释「raw target 已在机器人系」是**未验证声明**；外骨骼帧 vs 机器人帧是否固定变换未测（UBT P-012 坑：std 0.36m 的非固定差曾经骗过笛卡尔直比） | ⬜ |
| 控制器自有末端位姿 | 5566 JuxieLinker Web UI / 协议是否暴露末端位姿未知；`joint_probe` 只读关节 | ⬜ 待查 |

**建议动作（T20）**：① 先查控制器是否自带末端位姿输出（有 → 直接采 20 组
（q, 末端）对账；无 → 少量物理测量）；② 限位表三方对比（URDF/档案/真机实达）；
③ 对账必须含姿态维度；④ mirror_xyz 声明单独立项验证。详见 TASKS T20。
