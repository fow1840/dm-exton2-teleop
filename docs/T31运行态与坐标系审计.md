## 坐标系契约表

下表说明仓库源码的行为。所有话题的运行中发布节点、消息、时间戳和频率均需在现场实测。

| 话题 | 源码或交接证据 | frame_id 与坐标含义 | 现场还需确认 |
| --- | --- | --- | --- |
| /target_robot/left_ee/target | 交接记录为 Puppetry，IK 左侧订阅 PoseStamped | IK 读取 XYZ 和 XYZW 四元数，并用 header.stamp 做输入滤波。它不读取 frame_id，也不执行 TF 变换，直接把输入当作其参考系中的目标 | 发布节点、实际 frame_id（包括空值）、时间戳、XYZ/姿态轴和单位 |
| /target_robot/right_ee/target | 同左侧，由 IK 绑定到右侧目标 | 与左侧使用同一解释流程，但右侧独立执行方向与比例映射 | 单独核对发布节点与样本，再比较左右是否同一坐标约定 |
| /target_robot/left_ee/state | FK adapter 发布 PoseStamped。IK 也创建同名发布端，受运行态开关及离合条件控制 | FK 取 base_frame → left_ee_frame 的最新 TF。标准 launch 为 base_link → Link7L。IK 若发指令状态，以 ref_link 标注，标准 launch 为 base_link | 当前实际发送者、离合条件、frame_id 及对应的模型/工具帧 |
| /target_robot/right_ee/state | 同左侧，使用右臂状态发布端 | FK 标准 launch 为 base_link → Link7。IK 指令状态同样以 ref_link 标注 | 单独核对发送者、离合条件和样本 |
| /client_robot/joint_states | Bridge 发布 JointState，按 URDF 关节名称排成右七轴、左七轴，弧度 | Bridge 写入 base_link 和当前 ROS 时间。它可发布反馈快照，特定路径会用指令缓存代替。消息时间戳只能说明发布时刻 | 实际发布者、name 与 position 对应、消息率与反馈来源。消息率不能证明设备采样率 |
| /target_robot/joint_commands | IK 发布 JointState，Bridge 按 name 提取目标 | IK 写入当前 ROS 时间，未设置 frame_id。这里传递的是 URDF 名称对应的关节值 | 实际发布者、名称、时间戳和消息率。空 frame_id 应按原样记录 |

## 需区分的参数与行为

- IK 的标准 launch 将 root_link_name 和 ref_link_name 都设为 base_link。若参考帧在 URDF 中不存在，源码会回退到 root_link_name。现场要用加载的 URDF 和启动日志确认最终参考帧。 [IK launch](../ros2_ws/src/robot_ik_retargeting/launch/ik_retargeting.launch.py) · [参考帧回退](../ros2_ws/src/robot_ik_retargeting/robot_ik_retargeting/ik_node.py#L162)
- 每侧的 ArmPoseMap 在初始化时构建。非空 calib_file 优先，未配置文件才使用显式矩阵和比例。全零位置矩阵回退到该侧 mirror_xyz 的对角矩阵，缺省姿态矩阵回退到单位矩阵。ROS 参数读回值还要与当前进程的启动日志 pose_map 对照。publish_commanded_ee_state 在循环中读取。 [参数和构造](../ros2_ws/src/robot_ik_retargeting/robot_ik_retargeting/ik_node.py#L192) · [映射加载](../ros2_ws/src/robot_ik_retargeting/robot_ik_retargeting/ik_node.py#L399)
- FK 若启用 yield_when_clutch，任一侧离合按下都会抑制双侧 FK 状态。IK 只在 publish_commanded_ee_state 为真且有离合时发布指令状态。两个端点同时出现在 topic info 中并不能证明两者此刻都在发送。 [FK 条件](../ros2_ws/src/robot_fk_adapter/robot_fk_adapter/joint_to_pose_adapter.py#L44) · [IK 条件](../ros2_ws/src/robot_ik_retargeting/robot_ik_retargeting/ik_node.py#L605)
- 2026-11-06 19:00 的 T29 历史日志记录左侧实际映射 P_map=diag(-1,1,1)，姿态矩阵为单位矩阵，两种比例为 1.0。该轮记录 publish_commanded_ee_state=False，joint_commands 约 240 Hz。这些数据仅是历史对照。T30 的物理轴方向属于后续真机验证。 [历史 WORKLOG](../WORKLOG.md#L1211) · [T30](../TASKS.md#L566)

## 现场只读采集

1. 在已授权的现场 ROS 主机上，使用当前工作区环境。先从运行进程确认 ROS_DOMAIN_ID，按现场的实际值导出。运行下面的脚本，输出目录必须尚不存在。
2. 从 context.txt 对照候选进程 PID、所有者和 ROS 环境，确认运行节点与脚本使用的节点名一致。实际命名不同时可设置 T31_IK_NODE、T31_FK_NODE、T31_BRIDGE_NODE。
3. 汇总各参数文件以及六组 info、sample、rate。样本记录 frame_id、stamp 和实际消息。空 frame_id 标为空。超时或没有平均值标为未观测，单独记下当时离合状态。若已有操作员批准的遥操窗口，可旁路观察 target，采集本身不触发离合或运动。
4. 核对 IK 运行态 URDF、启动日志的 Reference Frame 和左右 pose_map，并与 FK 的基座和末端链接对应。如多个发布端同时存在且不能定位实际发送者，保持未验证。ROS topic hz 给出订阅端接收率，记录实际观察窗口。

~~~bash
T31_OBSERVATION=clutch_released bash tools/dm-exo/t31_readonly_audit.sh /path/to/new-private-capture
~~~

采集脚本为每个命令保存原始标准输出、错误输出及退出码。rate 采集有时限，收到有效统计后结束仍可返回 124。现场输出仅通过获准渠道交接，GitHub 记录脱敏结果。 [采集脚本](../tools/dm-exo/t31_readonly_audit.sh)

### 解除阻塞所需证据

需要现场按上述脚本返回采集结果。若现场主机无法直接访问 GitHub，可先通过已授权的本地渠道把采集脚本传到现场主机，再用当前 ROS 环境执行。至少要补齐运行节点和 ROS_DOMAIN_ID、要求的 IK 参数、六个话题的发布端和实测接收率，以及左右 target/state 的原始 header。若左右 target 的 frame_id 为空或坐标方向无证据，还需现场 Puppetry 配置或厂家坐标定义，才能关闭 T31。
