# URDF 数值重建采数方案（T39，2026-11-07）

> 目的：不依赖厂商 URDF/D-H，用真机 (q, get_tcp_pose) 样本拟合 DH 链，重建可用的
> 运动学模型（先 FK/对账用，IK 模型重建另走 T20/T29 联动）。
> 依据：T20 判 URDF 结构性不可修补（292~1895mm）；T39 预演实锤控制器运动学可用
> 标准 7R DH 链表示（真机 7 构型插值 0.1mm、LOO 5/7 折留出 0.2~3.4mm；见 WORKLOG 2026-11-07）。

## 一、真值源与数据约定

| 项 | 约定 | 出处 |
|---|---|---|
| 关节真值 | `get_joint_position`（17 维：0=腰, 1..7=L1..L7, 8..14=R1..R7, 15/16=头） | 协议 V0.3 §5 |
| TCP 真值 | `get_tcp_pose`（14 = left7+right7；四元数 **qw-first**，xyz 米） | 协议 V0.3 §6 |
| 腰 | **全程固定 0**（采数纪律；DH 链按固定基座拟合） | 本方案 |
| 另一臂 | 采数期间保持不动（compare/fit 按单臂判决） | T20 同规则 |
| 数据有效性 | 驱动后反馈必须变化（活性门，见 §三）；重复构型去重后入库 | T26 缓存签名防御 |
| 落盘格式 | jsonl：`{t, pose_idx, q17, tcp14, note}`，与 compare_fk/fit_dh 兼容 | sweep_calib.py |

## 二、样本量（ident_study 实测依据，非拍脑袋）

- 合成实验（URDF 链当虚拟真机，噪声 0.3mm/0.1°，增量续拟合）：
  **N=8 即达测试位置 median 1.0mm / max 3.0mm**，N=64 时 0.5mm/1.0mm（平台）。
  前提=激励近似均匀随机（`ident_study.py` 可复跑）。
- 真机采样做不到均匀随机（限位内缩+肘堵转禁区+驱动时间），且真机 LOO 有 2/7 折
  外推塌陷先例 → **按 60 位姿/臂**（≈7.5×合成下界）。
- **增量采集纪律**：首 8 个 → 拟合+LOO → 此后每 10 个重拟合一次 `fit_dh.py`，
  验证集 = 每 5 个抽 1 个；**验证 median ≤ 20mm 且 max ≤ 100mm 即可提前收窗**
  （20mm=机械臂绝对定位精度=残差下限）。

## 三、安全边界（全部先于采数生效）

1. **人员与使能**：操作员在场；5566 清故障 → **人工 enable** → **关闭网页**（网页占
   运动会话，30485 帧受理不执行）；`auto_enable=false` 红线不动。
2. **链路独占**：停 T3 bridge（TCP 30485 单连接）；确认无其他客户端占用。
3. **位姿约束**（gen_calib_poses.py 已内置）：get_config 实测限位内缩 0.15；
   肘堵转禁区 `J2<-1.5 ∧ J4>1.0` 剔除；J6 不顶限位；构型间距 ≥0.9rad。
4. **驱动护栏**（sweep_v2 全继承）：每帧从真机反馈出发；步进 0.005rad/帧；
   连续拒绝 ≥3 → stop_motion 清队；观测拒绝 → 步进减半；每步 device_state 复查，
   非 ready/idle 全停；长行程拆半程路点。
5. **途经禁区检查**（新增）：关节空间直线段 9 点采样，穿禁区即插脱困路点
   （J2 拉回 ≥-1.3 或 J4 压回 ≤0.9）。
6. **反馈活性门**（新增）：相邻采样构型距 ≥0.9rad 但反馈变化 <0.05rad → 判
   「反馈缓存/冻结」（T26 签名）→ 全停，该文件数据全部存疑不入库。
7. **执行节奏**：默认 dry-run 打印全部路点计划 → `--limit 3` 首段验证 → 全量；
   右臂有 J14（腕）堵转史，右臂窗口需操作员点头后才开始，慢动避极限。

## 四、窗口执行序列（每臂一个窗口，预算 ~25min）

- 中途任何 `program_run_failed` 节流、堵转签名（T28）、活性门触发 → 立即全停保留现场。

## 五、验收门（修复交付前，全部离线复算）

1. **配对纪律**：样本与原件逐字 diff（UBT 第 7 幕教训：抄串制造 176mm 假残差）。
2. **维度齐全**：位置与姿态两维度都回归（UBT M5②：只验位置漏 90°）。
3. **LOO 门**：验证集位置 median ≤ 20mm 且 max ≤ 100mm，姿态 median ≤ 2°。
4. **对照基线**：同批样本上 URDF 基线残差（compare_fk.py）必须显著差于 DH 模型，
   防止「两个模型都差」被误读。
5. **跨构型抽查**：采数后另摆 5 个工作位姿（窗口内顺手），DH 模型预测 vs get_tcp_pose，
   逐个 ≤20mm —— 真「外推」验收，不只靠随机划分。
6. **交付物**：DH 表（a/α/d/θ 偏移 + T_base/T_tool）→ `gen_sdk_urdf` 同源重建 URDF
   （UBT 方法论第 5 条）→ 与 T30 翻转表联动（符号层）→ compare_fk 全样本回归。

## 七、边界与风险

- 本方案修复的是 **FK/对账模型**（RViz、对账、碰撞检查底座）；IK 侧pink 模型重建与
  镜像/翻转表联动是后续任务（T29/T30 衔接）。
- 若 60 位姿后 LOO max 仍 >100mm → 「控制器 ≠ 标准 DH 链」嫌疑上升（耦合关节/非刚性层），
  证据齐全后转厂商报修清单（T20 已立项索取原生 URDF/D-H，两条路线互为备份）。
- get_tcp_pose 真值地位依赖协议实现正确（文档「单位：弧度」笔误先例）——首窗口先用
  重复读数复核噪声底与自洽性，异常先查活性/配对再怀疑模型。
