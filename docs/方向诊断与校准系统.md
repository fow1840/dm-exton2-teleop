# 方向诊断与校准系统（T29 落地文档）

> 2026-11-06 建立。回答「遥操作方向为什么乱、怎么查、怎么修、怎么验」。
> 结论依据：T20（URDF↔真机结构性不一致终审）、T27（上游无罪定责）、T29（控制语义确认）、T30（翻转表探针）。

## 一、数据流与坐标系（谁在哪个系里说话）

```
外骨骼(.15) ──MessageBridge──> /exoskeleton/joint_states (12关节, rad)
        │
        └─> Puppetry(vendor) ──> /target_robot/{side}_ee/state   ← 外骨骼末端位姿（锚定/相对化的源）
                     │                /ee_poses (2×7, Float32MultiArray)
                     ▼
              ik_node (T5)  ←── /clutch/{side}（离合）
                │  锚定: 按下瞬间记 exo0 与 robot0（真机反馈位）
                │  映射: _incremental_desired → master_slave_map.ArmPoseMap ★本系统
                ▼
        /target_robot/joint_commands (14关节, ~250Hz)
                     ▼
              exton_bridge (T3, StepPlanner 限幅/迟滞/lock-step)
                     ▼
              控制器(192.168.61.60:30485) ──canfd──> 电机
```

坐标系事实：
- **外骨骼末端**：Puppetry 给的 `{side}_ee/state`，其基系约定是 vendor 内部约定（黑盒）。
- **机器人端**：IK 全程在 URDF base 系里算；URDF base 系 ≠ 控制器 base 系（T20：同关节输入
  位置残差 292~1895mm、姿态 100~167°，结构性不一致，符号枚举救不回）。
- **控制器真值**：`get_tcp_pose`（14 维，qw-first 四元数，xyz 米）是唯一真机 TCP 真值源，
  但 TCP 30485 单连接，bridge 运行期间无法旁路查询（将来在 bridge 内加轮询才可流式获取）。
- 关节方向：控制器 `get_config` 软限位（2026-11-06 18:10 原文已存档）与 T30 翻转表探针。

## 二、问题分层（方向乱不是一件事，是三层）

| 层 | 症状 | 根因 | 修法 | 状态 |
|---|---|---|---|---|
| ① 关节方向层 | 单关节正反转反 | URDF 轴向 vs 真机 | T30 翻转表 → URDF axis + bridge 收发符号映射 | 探针就绪，符号层 [1,-1,1,-1,1,-1,1] 高置信，置换待真机 |
| ② 末端映射层 | 平移方向乱/轴交换/比例不适 | exo 系 ≠ 机器人 base 系 + mirror 只能翻符号 | **本系统**：ArmPoseMap 3×3 + 缩放，六方向标定 | **已实现，默认=旧行为** |
| ③ 运动学层 | 目标方向对、真机走向仍不对 | URDF↔控制器结构性不一致 | 厂商 URDF/D-H 或数值重建（T20 路线） | 等厂商，不可用软件修 |

**注意**：②修好后若真机 TCP 仍不跟，是③——这不是映射能救的（T29 已明示）。

## 三、映射模块（master_slave_map.py）

纯 numpy、无 ROS/pinocchio 依赖；ik_node 按臂各持一个 `ArmPoseMap`：

```
平移:  dp_robot = position_scale · P_map · (p_exo − p_exo0)
姿态:  ω_robot  = orientation_scale · sgn(det(Q)) · Q · log(R_exo·R_exo0ᵀ)
       R_des    = Exp(ω_robot) · R_robot0
```

安全设计（都写进了代码与测试）：
- **默认参数 == 2026-11-06 前旧行为**（P_map=diag(mirror), Q=I, scale=1），
  测试 A 类对 50 个随机位姿逐位断言与旧公式一致 → 部署即零行为变化；
- `validate()` 硬门禁：非正交映射阵 / 缩放出 [0.05,2] 范围 → 启动即报错退出，**禁止半生效**；
- 标定 JSON 格式 `arm_pose_map_v1`，格式不符拒绝加载；
- 伪向量 det 符号规则：镜像阵（det=−1）换基必须补负号，测试 C 类专项覆盖。

## 四、标定与验收流程（操作员手册）

前置：控制器已 enable、软件链 `restart_teleop.sh` 起全、bridge reject=0、**本系统已部署**。

### 4.1 平移六方向标定（~15 分钟）
1. 录制：`python3 ~/桌面/dm-exo/record_compare.py 90 sixdir_left`
   按住**左**离合，依次做 +X/−X/+Y/−Y/+Z/−Z 各一段：**慢速匀速 ~50mm，
   按-停1s-动-停1s-松**，段间完全松离合。右臂同法另录一段。
2. 分段诊断：`python3 ~/桌面/dm-exo/sixdir_calib.py segment sixdir_left.npz --side left`
   → 核对 6 段都被识别、主轴建议与你做的方向一致。
3. 回收当前映射（诊断）：`... fit sixdir_left.npz --side left --labels "0:+X,1:-X,2:+Y,3:-Y,4:+Z,5:-Z" --mode measured`
   → 打印当前链路实际的方向表（这就是操作员体感的「乱」的定量版）。
4. 写标定：同命令换 `--mode desired --position-scale 0.3 --out ~/桌面/dm-exo/calib_left_v1.json`
   （desired 模式下 labels 的含义=「这个方向我希望机器人就这么走」；scale 初值 0.3 见 T29 降敏）。
5. 部署：`ros2 param set` 不支持换文件，需重启 T5 带
   `-p calib_file_left:=/home/tc/桌面/dm-exo/calib_left_v1.json`（ik_node 启动日志会打印加载结果）。
6. 验收：再录一段 `sixdir_left_v2`，`... verify sixdir_left_v2.npz calib_left_v1.json --side left`
   → 每段误差 <3mm、≥3 段可用才 PASS。

### 4.2 姿态方向（分阶段，先不做）
T29 顺序：平移验收通过前，姿态 cost 保持 40 但操作员不转腕；平移 PASS 后
用 `orientation_map`/`orientation_scale`（初值 0.2）逐轴恢复。工具已支持参数，
真机姿态标定流程待平移验收后另写（需要 T30 翻转表先实锤关节层）。

### 4.3 关节方向（T30 探针，独立于上面的末端流程）
`pink/bin/python ~/tcvg/urdf_fk_calib/urdf_axis_probe.py <URDF路径> left`
（每关节 +0.12rad 去回微扰，操作员松离合、离 GUI、手离臂）。输出 ALIGNED/INVERTED
表落 WORKLOG 后，改 URDF axis 必须同步 bridge 收发两侧符号映射，先离线回归再真机。

## 五、安全门禁（硬规则）

1. 真机动作只在：操作员在场 + enable + 按离合的遥操路径上发生；探针类脚本每次真机
   微扰前需操作员逐项确认。
2. 标定文件加载失败 → ik_node 拒绝启动（宁可不起臂，不带错跑）。
3. `position_scale/orientation_scale` 合法域 [0.05,2]，配 0/放大器直接拒绝。
4. 降敏第二层：bridge `max_joint_step_rad` 可在线 `ros2 param set` 降（如 0.20→0.02），
   不改代码不重启。
5. 每次改标定 → 重启 T5 后必须确认 `publish_commanded_ee_state=False`（T11 条件，
   restart 脚本已固化，手动重启时要手动补）。
