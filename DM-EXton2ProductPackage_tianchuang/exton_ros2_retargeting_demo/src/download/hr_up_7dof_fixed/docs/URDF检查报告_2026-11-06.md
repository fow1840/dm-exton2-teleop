# 当前双臂 URDF 检查报告

检查日期：2026-11-06。检查对象为当前 FK / IK launch 使用的 `exton_ros2_retargeting_demo/src/hr_up_7dof_fixed/urdf/HR-UP-7DOF-3KG-R-B01382-URDF-1029.urdf`。

结论（2026-11-06 修复后）：已修复现有资料能够确定的左臂惯性坐标转换遗漏，当前模型可继续用于 RViz 关节运动演示。URDF 与真机桥接限位不一致、实机映射和 TCP 仍待真实资料确认；本次未改动这些控制参数，也未改变运动学、关节限位或网格。当前检查不能证明模型与实机运动学、动力学完全一致。

## 1. 已修复：左臂惯性坐标未随网格补偿同步调整

修复前，URDF 的 `Link1L`～`Link6L` visual / collision 都新增了 180° 旋转补偿，但 inertial 的质心位置仍逐项等于原始 SolidWorks CSV，inertial rpy 仍为零。CSV 中原始 visual 和惯性坐标系的 RPY 均为零，因此本次将惯性属性应用与现有网格相同的刚体旋转。

其中 `Link5L` 的问题可以直接量化：

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| visual / collision 旋转 | 绕 X 轴约 180° | 相同 |
| 旋转后 STL 网格 Z 范围 | 约 −0.24757～0 m | 相同 |
| inertial 质心 Z | +0.085510953 m | 约 −0.085510953 m |
| 质心超出网格包围盒 | 约 85.51 mm | 0 mm |

修复覆盖全部 6 个补偿连杆，而非只调整 `Link5L`。Link1L / Link3L / Link4L 同步绕 Z 轴补偿，Link2L / Link5L / Link6L 同步绕 X 轴补偿；使用与 visual 完全相同的 RPY 数值，包括原文件的有限精度。

影响：RViz 展示与纯运动学 FK / IK 不使用质量惯性，因此外观和关节滑动可以正常；动力学、重力补偿和物理仿真会受影响。

实施方式：质心按 `c_new = R_visual × c_CSV` 转换；惯性 origin 的 RPY 设为对应 visual 的 RPY，惯性坐标系内的张量数值和质量保持 CSV 原值。这样在 link 坐标系中的张量自然为 `R_visual × I_CSV × R_visualᵀ`，避免重复旋转张量或错误增加平行轴项。该修复校正坐标表达，不重新估算真实质量和惯性。

同步修改了 `exton_ros2_retargeting_demo/src/hr_up_7dof_fixed/` 和 `URDF/HR-UP-7DOF-3KG-R-B01382-URDF-1029-fixed/` 下的 URDF，保留各自根节点名称。原始 CSV 和历史 ZIP 压缩包没有改写；分发修复版时应使用修复后的解压目录，旧 ZIP 仍包含修复前内容。

验证结果：

- 两份 URDF 均通过 ROS Humble `check_urdf`。
- 两份模型各 15 个惯性连杆均通过 CSV 旋转转换、质量和张量数值保留、惯性正定性与质心包围盒检查。
- 回归检查能识别修复前全部 6 个左臂惯性错位。
- 与修改前 XML 比较，除 6 个 inertial origin 外，其他 XML 元素完全一致。
- 当前 `install_local` 使用源文件链接，已读取到修复内容，无需重新编译；已运行的节点需要关闭并重启才能重新加载。

## 2. 已确认：关节限位与真机桥接配置不一致

URDF 的全部 14 个关节均采用 ±2.967 rad（约 ±170°），注释明确说明是参考同类机械臂设置的值。各轴 effort=100、velocity=6.28 也统一填写，当前文件未给出实机标定依据。

`exton_ros2_retargeting_demo/scripts/exton_bridge.py` 的默认右臂限位来自档案并向内收缩 2°，与 URDF 不同：

| 右臂关节 | URDF 范围（约，度） | bridge 默认范围（度） |
| --- | --- | --- |
| Joint1 | −170～170 | −177.90～177.90 |
| Joint2 | −170～170 | −146.97～152.70 |
| Joint3 | −170～170 | −37.53～127.49 |
| Joint4 | −170～170 | −146.97～152.70 |
| Joint5 | −170～170 | −87.95～87.95 |
| Joint6 | −170～170 | −152.70～152.70 |
| Joint7 | −170～170 | −152.70～152.70 |

bridge 左臂又使用硬编码 ±3.09 rad（约 ±177.04°），名称虽为 `URDF_LIMITS_RAD`，实际没有读取当前 URDF 的 ±2.967 rad。

影响：GUI / IK 允许的目标与 bridge 实际裁剪范围不同，可能出现 RViz 可到、真机无法到达，或 IK 范围比 bridge 更窄的情况。需要根据每轴实机零位、正方向和厂家限位建立统一配置；不能直接把左右臂全部套成相同限位。

## 3. 需实机核对：镜像运动学及末端定义

URDF 注释明确写明左臂 Joint1L～Joint7L 的 origin 已重写，和厂商原始左臂定义不同。bridge 当前按关节名直接映射反馈与目标，没有针对这些变化进行逐轴符号 / 零位偏移变换。

数学一致性检查：100 组左右同角度随机姿态（每轴 −1～1 rad）下，左臂关节原点与右臂关于 base_link 的 XZ 平面镜像位置最大差约 7.19 微米，说明当前模型内部的镜像关系基本成立。该结果不能代替“实机同一关节正转时，模型是否同向”的验证。

FK / IK 目前使用 Link7 / Link7L 原点作为末端。URDF 中没有单独的工具 TCP 固定变换；如果目标是夹爪中心、法兰中心或实际工具端点，需要确认这些原点是否就是所需控制点。

## 4. 使用注意：零位是奇异构型

在全部关节为零时，以 Link7 / Link7L 原点构建的几何雅可比均为 6×7、数值秩为 5（阈值 1e−5）。这是当前直臂零位的运动学性质，不能单独判定为 URDF 错误。

影响：滑块直接控制关节不受影响；IK 从零位求解某些末端运动时可能困难。应结合求解器阻尼、姿态权重以及经验证的初始姿态评估，不能仅因零位 IK 表现不好就修改关节轴。
